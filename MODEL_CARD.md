# Model card: VisionGuard waste classifier

## Summary
| | |
|---|---|
| Task | Single-label image classification into 6 TrashNet classes: cardboard, glass, metal, paper, plastic, trash |
| Model | MobileNetV2 (torchvision, ImageNet-1k V2 weights), feature blocks 14+ and a new linear head fine-tuned |
| Selection | Highest validation macro-F1 among small CNN, frozen MobileNetV2, fine-tuned MobileNetV2 (chosen before the test set was evaluated) |
| Input | RGB image; resize 232, center crop 224, ImageNet normalization |
| Variants shipped | PyTorch checkpoint (9.2 MB, not in git), ONNX fp32 (8.9 MB), ONNX static int8 (2.6 MB), all regenerated by script |

## Intended use
Educational and portfolio demonstration of a reproducible transfer-learning pipeline with leak-aware evaluation and explanations. **Not** for deciding what a person may recycle, for industrial sorting, or for any safety-relevant decision.

## Training and evaluation data
TrashNet (Thung and Yang), 2,527 images, 2,521 after removing six images in three exact-duplicate groups with conflicting labels. Split by perceptual-hash groups into 1,763 train, 379 validation, 379 test (seed 42; manifest in `reports/split-manifest.json`). Images are mostly one item on a plain white or gray background.

## Results (held-out test, 379 images, one training seed)
Reproduce: `python -m vg evaluate --run runs/baseline`, then `python scripts/bootstrap_ci.py`.

| Metric | Value | 95% bootstrap CI (test-set resampling) |
|---|---:|---:|
| Macro-F1 | 0.8975 | 0.858 - 0.930 |
| Accuracy | 0.9129 | 0.884 - 0.939 |

| Class | Test images | F1 | 95% CI |
|---|---:|---:|---:|
| cardboard | 60 | 0.958 | 0.917 - 0.992 |
| glass | 78 | 0.923 | 0.875 - 0.963 |
| metal | 61 | 0.886 | 0.824 - 0.940 |
| paper | 90 | 0.925 | 0.882 - 0.963 |
| plastic | 71 | 0.913 | 0.857 - 0.960 |
| trash | 19 | 0.781 | 0.609 - 0.905 |

The CIs reflect test-set sampling only. Training-seed variance is **not** measured (one seed), so differences of a couple of points between models should not be over-read. The weakest class (trash, 19 test images) has a very wide interval.

### Compression (same test images; `python scripts/onnx_benchmark.py`)
| Variant | Size | Macro-F1 | Top-1 agreement with PyTorch | Batch-1 CPU latency, median / p95 |
|---|---:|---:|---:|---:|
| PyTorch fp32 | 9.16 MB | 0.8975 | - | 49.2 / 65.8 ms |
| ONNX fp32 | 8.90 MB | 0.8975 | 100% (max logit diff 4e-5) | 8.2 / 20.7 ms |
| ONNX static int8 | 2.62 MB | 0.8885 | 97.6% | 5.9 / 13.4 ms |

Latency: model only (tensor already preprocessed), 3 rounds x 100 runs after warm-up, 13th Gen Intel Core i5-13420H laptop, PyTorch with 4 threads versus onnxruntime default threads, on a shared machine with other jobs running. Indicative, not a benchmark. int8 calibration used 100 training images; it costs 0.9 macro-F1 points here.

## Explanations
Grad-CAM on the last convolutional block (`python -m vg explain IMAGE`, `POST /explain`). Galleries of the first six correct and first six wrong test predictions are in `reports/gradcam_correct.png` and `reports/gradcam_errors.png` (manifest order, not cherry-picked). Grad-CAM shows which regions influenced a score; it is not proof of correct reasoning. In the error gallery several mistakes (a plastic-wrapped cardboard box, a glass jar read as plastic, a metal lid on glass) are plausible material confusions.

## Limitations and risks
- Plain-background benchmark images; **no independent phone-photo evaluation has been done**, so real-world accuracy is unknown and expected to be lower.
- No "unknown object" class: "trash" is a dataset label, not an out-of-distribution detector. Softmax scores are not calibrated probabilities. The abstain threshold (0.40) rejects only 1 of 379 test images, so it is nearly inactive.
- One item per photo; no multi-object detection. No fairness-relevant person data, but images come from a small set of sources and locations.
- Single seed and a single random split.

## Maintenance
Retrain with `python -m vg train`; the code refuses to overwrite an existing run. Pinned dependencies are in `requirements-lock.txt`.
